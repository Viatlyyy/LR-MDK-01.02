# Демо-экзамен: авторизация и карточки товаров

Откройте `WindowsFormsApp1.sln` в Visual Studio с компонентами Windows Forms и .NET Framework 4.7.2, восстановите NuGet-пакеты и соберите решение. Готовый запуск — `App/WindowsFormsApp1.exe`.

При запуске сначала открывается `LoginForm`: введите подготовленный логин и нажмите «Войти» или Enter. Пароль не требуется. Неизвестный или пустой логин оставляет окно входа открытым и показывает ошибку. Кнопка «Отмена», клавиша Esc или закрытие окна входа завершают запуск приложения, не открывая главную форму.

`DemoLib/Models/IAuthorization.cs` задаёт метод `Authorize(string login)`. Класс `Authorization` реализует его и хранит в коде всех 20 пользователей из `Users_import.xlsx`; подключение БД на этом шаге не используется. Найденный пользователь возвращается как `User` с логином, ФИО и ролью, при неудачном входе возвращается `null`. Внешние пробелы удаляются, регистр логина учитывается. `AuthorizationPresenter` связывает эту проверку с `IAuthorizationView`, реализованным формой входа.

Примеры логинов: `isivanov` — Иванов Иван Сергеевич, администратор; `papetrov` — Петров Пётр Алексеевич, менеджер; `asidorova` — Сидорова Анна Дмитриевна, авторизованный пользователь. Полный список находится в `Authorization.cs`.

После входа главная форма показывает заголовок страницы, исходный логотип «Чудо Обувь», ФИО, роль и значок авторизованного пользователя. Под заголовком расположен стандартный `TabControl` с двумя `TabPage`: «Карточки» и «Заказы». На первой вкладке находятся карточки товаров, вкладка заказов пока пустая. Переключение сохраняет существующие карточки и не применяет скидку повторно. Обе формы имеют `Designer.cs` и `resx` для редактирования в Visual Studio. Логотип и иконка взяты из ресурсов экзамена и встроены в приложение.

Оформление сверено с руководством по стилю (Приложение 3) и макетом каталога в КИМ: шрифт Calibri, основной фон `#FFFFFF`, дополнительный `#D2F6E7`, акцент `#70B2AF`, подсветка товаров с остатком не более трёх пар `#FF8080`. ФИО находится справа вверху, исходный логотип отображается с сохранением пропорций. В документах нет численных требований к кеглю, размерам окон и отступам. В проекте базовый шрифт форм и карточки — Calibri 12 пт, заголовки форм — 22 пт; размеры текста карточки сохранены. Масштабирование карточки настроено под её базовый шрифт.

В `DemoTesting/TAuthorization.cs` находятся четыре простых теста авторизации: известный логин возвращает пользователя с правильными ФИО и ролью; неизвестный логин, пустая строка и `null` возвращают `null`. Каждый сценарий — отдельный метод без параметризации, моков, вспомогательных классов и методов. Вместе с прежними восемью проверками `UpdatePrices` выполняются 12 тестов.

`DemoLib/Repositories/IOrdersRepository.cs` объявляет `IEnumerable<Order> Load()`. Модель использует один метод `UpdatePrices(IOrdersRepository ordersRepository)`: проверяет репозиторий, загружает заказы один раз и применяет существующее правило скидки 25% за отсутствие продаж в предыдущем календарном месяце. Метод принимает только интерфейс репозитория. Если репозиторий равен `null`, метод завершает работу через `return`, сохраняя цены.

При обычном запуске `Program` создаёт `DemoOrdersRepository` и передаёт его в `MainForm(IOrdersRepository ordersRepository)`. При загрузке формы вызывается `UpdatePrices`, который загружает заказы через интерфейс и пересчитывает цены перед отображением карточек. `DemoOrdersRepository` — временный источник без БД: он возвращает пустую последовательность заказов, сохраняя поведение исходного проекта. Поэтому при обычном запуске все товары получают скидку 25%.

Реальное подключение БД на этом этапе не реализовано. Позже вместо `DemoOrdersRepository` можно передать реализацию для БД, сохранив интерфейс и расчёт модели. Обычный конструктор `MainForm()` сохранён для конструктора форм. Если форму создать без репозитория, отображаются исходные цены, перерасчёт не выполняется.

В `DemoTesting/TOrder.cs` находятся все 8 тестов метода `UpdatePrices` без собственных вспомогательных классов и методов подготовки данных. В семи тестах мок `IOrdersRepository` создаётся прямо в тесте через Moq: `Setup(...).Returns(...)` задаёт загружаемые заказы, а `repository.Object` передаётся модели. Шесть прежних сценариев сохраняют данные и ожидаемые результаты. Основной мок-тест дополнительно проверяет один вызов загрузки через `Verify(..., Times.Once())`, сохранение цены проданного товара и скидку для непроданного. Отдельный тест проверяет сохранение цены при `null` вместо репозитория. Пакеты Moq и его зависимости указаны в `packages.config` и восстанавливаются NuGet. Запуск: **Тест → Запустить все тесты**.
